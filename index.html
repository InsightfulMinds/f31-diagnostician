An F31 diagnostician I built and then forgot to submit

August 9, 2026

This was built for a competition with a hard deadline of 11:59 PM the night before this post. The build finished, passed its own verification gate, and then sat there waiting on a final go that never came because I didn't get around to it. So instead of a submission, it's a repo. Posting it for fun.

What it is: a pipeline that reads a graduate fellowship application (the NIH F31 kind) alongside its reviewer critique and works out why it scored the way it did. Five stages: intake, extraction, matching against a table of known failure modes, verification, and a diagnosis write-up. If the critique doesn't actually match any known failure mode, it refuses to invent one and writes a no-diagnosis file instead. That refusal path is tested.

What I like about it

  • The whole thing is plain markdown contracts and a shell verify gate. No framework. An agent lands in the repo, reads one 42-line entry file, and knows where it is and what to do next.
  • The gate has 78 checks and, more importantly, a selftest that injects four defects to prove the gate can fail. During the build it caught a real bug in itself: a grep flag that BSD grep silently ignores, which had it passing on a tree that should have failed.
  • Reconstructed example cases are labeled as reconstructed on line one, and a negative-control case exists where the correct answer is "no diagnosis."

Where to look

  • README.md, then the how-to-run section.
  • verify-evidence.txt for the full gate output and the walk-test transcript.
  • _shared/rules/failure-modes.md for the diagnosis table itself.

Would it have placed? No idea. That's part of the fun of shipping it late.
